디바이스 제어 모듈을 인계받아 운영하며 HTTP 기반 등록 흐름을 MQTT 상시구독으로 재설계했습니다.

디바이스 등록 흐름 재설계 (HTTP → MQTT 상시구독)
1
Before: API 트리거 기반 구독
디바이스가 특정 REST API를 먼저 호출해야 그때부터 MQTT를 구독(10초 대기)하는 구조였습니다 — 구독 전에 발행된 메시지가 유실되는 타이밍 레이스가 있었습니다.
재설계
2
After: MQTT 상시 구독
애플리케이션이 기동되는 시점부터 MQTT를 상시 구독하도록 전환했습니다. 기존에 등록 메시지와 상태알림 메시지로 나뉘어 있던 것을 단일 메시지로 합쳐 수신 → 다단계 검증·처리 → 결과 메시지 발행.
3
Shared Subscription 이중화
AWS IoT Core의 공유구독(Shared Subscription)을 적용해 인스턴스 중 1대만 메시지를 수신하도록 했습니다 — 코드 변경 없이 단일/이중화 환경을 동일하게 운영할 수 있습니다.
4
등록 검증 N+1 → 1회
요소마다 개별 조회하던 검증 로직을 DB 1회 조회 후 단일 순회(O(1))로 통합했습니다.
구펌웨어 대응을 위해 기존 REST 기반 등록 확인 엔드포인트는 당분간 병행 운영하며, 클라이언트 쪽 전환이 완료되는 대로 단계적으로 정리할 예정입니다.

Security블로그
OAuth2 JWT 이중화 이슈
재기동 시 전체 사용자 로그아웃
Background

이중화 환경에서 무중단 배포를 시도하던 중 발견했습니다. 서버가 기동될 때마다 RSA 키를 메모리에서 새로 생성하는 구조여서 인스턴스마다 키가 달랐고, 이 때문에 Sticky Session에 의존할 수밖에 없었습니다. 서버 재기동 시 전체 사용자가 로그아웃되는 현상이 발생했습니다.

Decision

AWS 콘솔 볼륨 리사이즈 → growpart 파티션 확장 → xfs_growfs 파일시스템 확장 → df -h 검증까지 4단계를 무중단으로 진행해 완료했습니다. 신규 프로젝트의 Self-hosted Runner를 포함한 인프라가 정상 동작할 수 있는 용량을 확보했습니다.

내부 네트워크 경로 최적화
외부 ALB 경유 → Internal NLB + Private DNS
Background

내부 서비스 간 통신이 외부 ALB를 경유하는 구조여서 불필요한 왕복 레이턴시가 발생했습니다. 간헐적인 Timeout 이슈가 생겼고, 외부 통신 비용도 함께 증가하는 문제가 있었습니다.

Decision

hosts 파일을 직접 수정하는 방법은 단기 패치에 불과하고 서버별 관리가 어렵다고 판단했습니다. Internal NLB와 Private DNS를 도입하면 인프라 수준에서 근본적으로 해결되고, 재현·롤백·확장이 모두 용이한 구조가 된다고 분석했습니다.

Result

Internal NLB와 Private DNS를 도입해 내부 트래픽을 VPC 내부로 직접 라우팅하는 방안을 설계하고 제안했습니다. 외부 ALB 경유 제거로 레이턴시가 감소하고, 불필요한 외부 통신 비용 절감 효과를 기대할 수 있었습니다.

AWS IoT블로그
OTA Lambda 역할 분리 및 구조 개선
단일 Lambda 다목적 처리 → 책임 분리 2개 Lambda
Background

ota-job-handler 하나가 Job 생성·삭제·초기 등록·상태 업데이트를 모두 처리하는 구조여서 역할이 불명확했습니다. OTA 진행 중 신규 디바이스가 ThingGroup에 추가될 때 DB에 누락되는 케이스가 존재했습니다.

Decision

단일 Lambda 내 분기 처리로 수정하는 방법도 검토했지만, 이벤트 트리거 소스 자체가 달라 자연스러운 분리 경계가 존재했습니다. 역할을 분리하면 장애 발생 시 영향 범위가 줄어들고 각 Lambda의 책임이 명확해진다고 판단했습니다.

Result

ota-job-handler(Job 생명주기)와 ota-status-handler(상태 업데이트)로 역할을 분리했습니다. AddThingToThingGroup 이벤트 처리를 추가하여 신규 디바이스 누락 케이스를 선제적으로 방어했습니다.
